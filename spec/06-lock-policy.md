# 06. 잠금 정책과 세션

"잠겨 있다"의 정의는 하나다: **VK가 메모리에 없고 DB 핸들이 닫혀 있다.**
화면을 가리는 것만으로는 잠근 것이 아니다.

## LOCK-01 세션 상태

```
       ┌──────────────────────────────────────┐
       │                                      │
       ▼                                      │
   ┌────────┐  해제 시도   ┌───────────┐      │ 잠금 트리거
   │ LOCKED │ ───────────▶ │ UNLOCKING │      │ (LOCK-03)
   └────────┘ ◀─────────── └───────────┘      │
       ▲        실패/취소         │ 성공        │
       │                          ▼            │
       │                   ┌──────────┐        │
       └───────────────────│ UNLOCKED │────────┘
         잠금 트리거         └──────────┘
```

| 상태 | VK | DB 핸들 | UI |
|------|-----|---------|-----|
| `LOCKED` | 없음 | 닫힘 | unlock 화면만 ([UX-02](05-ui-flows.md)) |
| `UNLOCKING` | 없음 | 닫힘 | 진행 표시. 입력 비활성 |
| `CREATING` | 없음 | 닫힘 | 온보딩의 생성 진행 표시 ([UX-01](05-ui-flows.md) 3단계). `UNLOCKING` 의 변형 — 해제 화면이 아니라 온보딩에 머물기 위해 따로 둔다 |
| `UNLOCKED` | 보유 | 열림 | 전체 기능 |
| `NO_VAULT` | 없음 | 닫힘 | 온보딩 ([UX-01](05-ui-flows.md)). `vault_meta` 가 `Absent` |
| `CORRUPT` | 없음 | 닫힘 | "금고를 열 수 없습니다" ([ARC-06](04-architecture.md)). `vault_meta` 가 `Corrupt` |

`NO_VAULT` 와 `CORRUPT` 는 `LOCKED` 의 변형이다 — VK 가 없고 DB 가 닫혀 있다는 불변식이 같다.
화면 분기를 위해 따로 둔다. 판정 근거는 DM-01 의 읽기 3분류다.

- 상태는 `SessionManager` 의 `StateFlow<SessionState>` 하나로만 표현한다.
  잠금 여부를 판단하는 두 번째 소스를 만들지 않는다.
- 앱 프로세스 시작 시 항상 `LOCKED` 다. 상태를 디스크에 저장하지 않는다.

## LOCK-02 VK 보유 규칙

- VK 바이트는 `SessionManager` 인스턴스 안에만 존재한다.
- 외부는 `withVaultKey { key -> ... }` 로 **빌려 쓴다.** 참조를 복사해 보관하지 않는다 (SEC-12).
- `UNLOCKED` 가 아닌 상태에서 `withVaultKey` 호출은 예외가 아니라 실패 결과를 반환한다
  (잠금과 동시에 진행 중이던 작업이 있을 수 있다).

## LOCK-03 잠금 트리거

| 트리거 | 조건 | 설정 |
|--------|------|------|
| 유휴 타임아웃 | 마지막 사용자 상호작용 후 `autoLockSeconds` 경과 | UX-08 |
| 백그라운드 전환 | `ON_STOP`. `lockOnBackground` 가 true면 즉시 | UX-08 |
| 수동 잠금 | 설정 또는 목록 화면의 잠금 버튼 | 항상 |
| 화면 꺼짐 | `ACTION_SCREEN_OFF` 수신 | 항상 |

생체 정보 변경(Keystore 키 무효화)은 **잠금 트리거가 아니다.** 무효화는 키를 쓰려는 순간에만 드러나므로
다음 생체 해제 시도에서 처리한다 — 래핑을 지우고 비밀번호로만 해제하게 한다 ([CRY-13](02-crypto.md) 4 단계).

구현 메모:
- 유휴 타이머는 **벽시계가 아니라 단조 시계**(`SystemClock.elapsedRealtime`)로 센다.
  사용자가 시스템 시간을 바꿔 잠금을 회피하지 못하게 한다.
- 타이머는 백그라운드에서도 유효해야 한다 → 백그라운드로 간 시각을 기록하고,
  포그라운드 복귀 시 경과 시간을 비교해 판정한다. 포그라운드에서만 도는 타이머로는 부족하다.
- 사용자 상호작용 감지는 `Activity.onUserInteraction()` 과 Compose 입력 이벤트 양쪽을 쓴다.
  **소프트 키보드 입력은 `onUserInteraction` 을 지나지 않는다** — 키보드는 다른 창이고 글자는 `InputConnection` 으로
  들어온다. 앱 루트의 입력 인터셉터(UX-06)에서 `InputConnection` 의 편집 호출(글자 입력·조합·삭제·키·편집 동작)을
  상호작용으로 센다. 빠뜨리면 긴 메모를 쓰는 도중에 잠겨 입력이 사라진다.
  화면을 보고만 있는 것은 상호작용이 아니다 (의도된 동작).
- `AlarmManager`·`WorkManager` 를 쓰지 않는다. 프로세스가 죽으면 이미 잠긴 것이다.
- 화면 회전 등 구성 변경은 백그라운드 전환이 아니다 (`isChangingConfigurations` 면 무시).
- 해제되는 순간 유휴 시작점을 지금으로 맞춘다. 생체 해제는 화면을 건드리지 않으므로,
  그렇지 않으면 오래된 상호작용 시각 때문에 해제 직후 바로 다시 잠긴다.
- 백그라운드 경과는 따로 재지 않고 마지막 상호작용으로부터의 경과로 본다 — 백그라운드에 있던 시간은
  상호작용이 없던 시간이다. 포그라운드 복귀(`ON_START`) 시 화면을 그리기 전에 판정한다.
- 화면 꺼짐 수신기는 프로세스 전역(Application)에 둔다. 앱이 백그라운드여도 잠근다.
- **예외 — 우리가 연 시스템 파일 선택기(SAF)**: 백업 내보내기·가져오기(BK-03·04)는 시스템 파일 선택기를
  띄우고, 그 순간 앱은 `ON_STOP` 을 받는다. 백그라운드 즉시 잠금을 그대로 적용하면 파일을 고르고 돌아왔을 때
  금고가 닫혀 있어 백업이 불가능하다. 선택기를 띄운 순간부터 결과를 받을 때까지만 **백그라운드 즉시 잠금을
  보류**한다. 유휴 시간과 화면 꺼짐은 그대로 적용된다 — 선택기에서 오래 머물면 돌아오는 즉시 유휴 판정으로 잠긴다.

## LOCK-04 잠금 절차

순서가 중요하다. 중간에 실패해도 더 안전한 쪽으로 끝나야 한다.

```
1. 상태를 LOCKED 로 먼저 전환 (UI가 즉시 가려진다)
2. 백스택 비우고 unlock 으로 이동 (UX-00)
3. DB 핸들 close
4. 메모리 캐시(목록, 상세, ViewModel 보관값) 폐기
5. zeroize(VK)
6. **수동 잠금·화면 꺼짐일 때만** 클립보드가 이 앱이 넣은 내용을 담고 있으면 삭제 (LOCK-07)

   백그라운드·유휴 잠금에서는 지우지 않는다. 복사의 주 용도는 다른 앱으로 넘어가 붙여넣는 것이고
   백그라운드 잠금이 기본값이라, 잠글 때마다 지우면 붙여넣기가 원천적으로 불가능해진다 (M7 에서 발견한
   LOCK-03·LOCK-04·UX-05 충돌). 그 경우는 자동 삭제 타이머가 맡는다. 수동 잠금과 화면 꺼짐은
   사용자가 "끝냈다"는 신호다.
```

**4 단계는 잠기는 즉시, 컴포지션과 무관하게 실행한다.** 백그라운드에서는 컴포지션이 멈춰 있어 2 단계(화면 전환)가
복귀한 뒤에야 일어난다. ViewModel 폐기를 화면 전환에 묶어 두면 그 사이 살아 있는 ViewModel 이 복귀 순간 닫힌 DB 를
다시 읽으려다 앱이 죽고, 복호화된 값도 그때까지 메모리에 남는다. 구현은 3 단계보다 4 단계를 먼저 실행한다 —
DB 를 쓰는 쪽을 먼저 멈추고 나서 닫는다.

## LOCK-05 해제 실패 백오프

| 누적 실패 | 대기 |
|-----------|------|
| 1–4회 | 없음 |
| 5회 | 30초 |
| 6회 | 1분 |
| 7회 | 5분 |
| 8회 이상 | 15분 (고정) |

- 실패 상태를 `vault_meta` 에 **저장한다** (DM-01). 앱을 재시작해 우회하지 못하게 한다.
- 대기 판정은 벽시계와 단조 시계를 **둘 다** 보고 남은 시간이 더 긴 쪽을 택한다.

단조 시계(`elapsedRealtime`)는 저장하지 않으면 앱 재시작 때 사라지고, 재부팅하면 0 으로
돌아간다. 그래서 실패 시점의 **부팅 번호**(`Settings.Global.BOOT_COUNT`, 권한 불필요)와 함께 저장한다.

```
실패 시 (벽시계 W, 단조 E, 부팅 B, 대기 P):
  lockoutUntilEpochMs   = W + P
  lockoutBootCount      = B
  lockoutUntilElapsedMs = E + P

남은 시간 = max( lockoutUntilEpochMs - 지금 벽시계,
                 같은 부팅이면 lockoutUntilElapsedMs - 지금 단조 시계, 아니면 0 )
```

| 공격 | 결과 |
|------|------|
| 시계를 앞으로 돌림 | 단조 시계 기한이 남아 막힘 |
| 앱 강제 종료 후 재실행 | 저장된 두 기한이 그대로라 막힘 |
| 시계 조작 + 앱 재실행 | 같은 부팅이므로 단조 시계 기한으로 막힘 |
| **재부팅 + 시계 조작** | **막지 못한다.** 재부팅 후에는 벽시계만 남는다. 수용하는 한계다 — 대기 상한이 15분이고 재부팅 자체에 시간이 들어 이득이 작으며, 실질 방어는 Argon2id 비용(SEC-02)이다 |
| 시계를 뒤로 돌림 | 벽시계 기한이 늘어 더 오래 기다릴 뿐 (사용자만 손해) |
- 해제 성공 시 두 값을 0으로 초기화한다.
- 생체 해제 실패는 `BiometricPrompt` 자체 잠금에 맡기고 이 카운터에 더하지 않는다.
- **데이터를 자동 삭제하지 않는다** (SEC-09 / [02](02-crypto.md) 제외 대안).

## LOCK-06 화면 보호

| 항목 | 구현 |
|------|------|
| 스크린샷·화면 녹화·최근앱 미리보기 차단 | `MainActivity.onCreate` 에서 `WindowManager.LayoutParams.FLAG_SECURE`. Activity가 하나이므로 한 곳에서 끝난다 |
| 예외 | **없다.** 디버그 빌드에서도 끄지 않는다. 스크린샷이 필요하면 임시로 로컬에서 주석 처리하고 커밋하지 않는다 |
| 키보드 학습 | 비밀 입력 필드에 IME 개인화·자동수정 비활성 (UX-06) |

## LOCK-07 클립보드

| 항목 | 구현 |
|------|------|
| 민감 표시 | `ClipDescription` 에 `EXTRA_IS_SENSITIVE = true` — 시스템이 미리보기 토스트에 내용을 띄우지 않는다 |
| 자동 삭제 | `clipboardClearSeconds` 후 삭제. 수동 잠금·화면 꺼짐 때는 즉시 삭제하고, 백그라운드·유휴 잠금 때는 지우지 않는다 (LOCK-04 6 단계) |
| 삭제 방법 | 복사할 때 클립에 임의의 표식(nonce)을 넣는다. 지울 때 현재 클립의 표식이 같으면 지운다. 다른 앱이 그 뒤에 복사했으면 지우지 않는다 |
| 확인할 수 없을 때 | Android 10+ 에서 **포커스가 없는 앱은 클립보드를 읽을 수 없다** (`getPrimaryClipDescription` 이 null). 타이머가 백그라운드에서 끝나면 소유를 확인할 수 없다. 이때는 **지운다** — 비밀이 클립보드에 남아 다음에 포커스를 얻는 앱이 읽을 수 있는 위험이 더 크다. 대가로 그 사이 다른 앱에서 복사한 내용이 지워질 수 있다 |
| 사용자 고지 | 복사 시 "N초 후 클립보드에서 삭제됩니다" 스낵바 |
| 한계 | 타이머는 프로세스 안에서 돈다. 시스템이 그 전에 프로세스를 죽이면 지우지 못한다 (Android 13+ 는 시스템이 일정 시간 뒤 클립보드를 비운다). `AlarmManager` 로 프로세스를 되살리지 않는다 — LOCK-03 과 같은 원칙 |
