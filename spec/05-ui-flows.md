# 05. 화면과 플로우

단일 Activity + Compose Navigation. 화면 목록과 각 화면의 **규칙**만 정의한다.
색·여백 등 시각 디테일은 스펙 대상이 아니다 (Material 3 기본을 따른다).

## 내비게이션 그래프

```
                      앱 시작
                         │
         vault_meta 존재? ─── 아니오 ──▶ onboarding (UX-01)
                 │                            │ 금고 생성 완료
                 예                           ▼
                 └──────────────────────▶ unlock (UX-02)
                                              │ 해제 성공
                                              ▼
                                          list (UX-04)
                                         ╱     │     ╲
                                   detail   settings  edit(신규)
                                   (UX-05)  (UX-08)   (UX-06/07)
                                      │
                                   edit(수정)
```

**UX-00 전역 규칙**: 세션이 `LOCKED` 로 바뀌면 ([06](06-lock-policy.md)) 어느 화면에 있든
백스택을 전부 비우고 `unlock` 으로 간다. 입력 중이던 내용은 버린다 (저장하지 않는다).

구현: 최상위 Composable 이 세션 상태로 분기한다. `NavHost` 는 `UNLOCKED` 분기 **안에만** 둔다.
잠기면 그 분기가 컴포지션에서 통째로 빠지므로 백스택·입력 상태·화면별 ViewModel 이 함께 사라진다.
백스택을 하나씩 꺼내는 방식보다 빠뜨릴 경로가 없다.

**UX-00b 비밀 입력값은 저장 상태에 넣지 않는다 (SEC-01)**: `rememberSaveable`,
`rememberTextFieldState()`, `SavedStateHandle` 은 값을 Activity 저장 번들에 넣고, 시스템은 프로세스를
종료할 때 그 번들을 **디스크에 기록**한다. 마스터 비밀번호와 항목의 비밀 필드는 `remember { TextFieldState() }`
처럼 저장되지 않는 상태에만 둔다. 화면 회전 시 입력이 지워지는 것은 감수한다.

## UX-01 온보딩 (금고 생성)

단계:

1. **소개 + 경고.** "마스터 비밀번호를 잊으면 데이터를 복구할 수 없습니다"를 명시하고
   체크박스로 확인받는다 (NFR-05). 체크 없이는 다음으로 못 간다.
2. **마스터 비밀번호 입력 + 확인 입력.**
   - 최소 길이 **12자** 강제. 그 이상 복잡도 규칙은 강제하지 않는다 (길이가 더 효과적이다).
   - 강도 표시 — 길이 기반 + 흔한 비밀번호 목록(앱 내장 소량) 대조. 약해도 진행은 막지 않는다.
     | 등급 | 조건 |
     |------|------|
     | 약함 | 흔한 목록에 있음(대소문자 무시), 또는 한 문자 반복 |
     | 보통 | 12–15자 |
     | 강함 | 16–19자 |
     | 매우 강함 | 20자 이상 |
   - 두 입력 불일치 시 진행 불가.
3. **생성 진행 표시.** Argon2id 캘리브레이션 + 금고 생성 ([CRY-09](02-crypto.md), CRY-10).
   수 초 걸릴 수 있음을 알리고 취소 불가로 둔다 (중간 취소 시 메타가 깨질 위험).
4. **(선택) 생체 해제 등록.** 기기에 Class 3 생체가 등록돼 있을 때만 노출 (CRY-14).
   "나중에" 선택 가능.
5. **(선택) 백업 안내.** 지금 백업하거나 건너뛴다 ([07](07-backup.md)).

## UX-02 잠금 해제

- 마스터 비밀번호 입력 필드 + 해제 버튼.
- 생체 해제가 설정돼 있으면 **화면 진입 시 자동으로** `BiometricPrompt` 를 띄운다 (CRY-13).
  사용자가 취소하면 비밀번호 입력으로 돌아간다. 생체 버튼으로 재시도 가능.
- 실패 시: "비밀번호가 올바르지 않습니다"만 표시. 남은 시도 횟수는 보여주지 않는다.
- 백오프 중에는 입력 비활성 + 남은 시간 카운트다운 ([LOCK-05](06-lock-policy.md)).
- 하단에 "백업 파일에서 복구" 진입점을 둔다 — 금고를 열 수 없는 사용자의 유일한 출구다 ([BK-05](07-backup.md)).

## UX-03 재인증 다이얼로그

민감 동작 전에 마스터 비밀번호를 다시 받는다. 대상:

- 생체 해제 등록 (CRY-12)
- 마스터 비밀번호 변경 (CRY-15)
- 백업 내보내기 ([BK-03](07-backup.md))

해제된 세션이라도 생략하지 않는다. 기기를 잠깐 빌린 사람(T-02)을 막는 장치다.

## UX-04 항목 목록

- 상단: 검색 필드. `entry.title` / `entry.subtitle` 부분 일치 (대소문자 무시).
  SQLite `LIKE` 로 DB 에서 거른다. `%`·`_` 는 이스케이프한다. 대소문자 무시는 ASCII 범위다 (한글은 해당 없음).
- 타입 필터 칩: 전체 / 로그인 / 메모 / 카드 / 신분증.
- 정렬: 즐겨찾기 먼저 → `title` 오름차순. 정렬 옵션은 제공하지 않는다.
- 각 행: 타입 표시, `title`, `subtitle`, 즐겨찾기 토글.
  즐겨찾기 토글은 `entry` 한 행만 `UPDATE` 한다 (`REPLACE` 금지 — CASCADE). `updatedAt` 은 바꾸지 않는다
  (내용 변경이 아니다).
  - 로그인 항목 중 정책 위반이 있으면 경고 배지. `entry.hasPolicyViolation` /
    `entry.hasRotationDue` 캐시만 읽는다 ([DM-03](03-data-model.md#dm-03-entry-공통)).
    목록에서 비밀번호를 복호화해 검사하지 않는다.
- **비밀 필드는 목록에 절대 나타나지 않는다** (NFR-02, [01](01-threat-model.md) T-02).
- 빈 상태: 첫 항목 추가 안내.
- FAB → 타입 선택 → `edit`(신규).

## UX-05 항목 상세

- 비-비밀 필드는 그대로 표시.
- **비밀 필드는 기본 마스킹.** 눈 아이콘으로 토글하며, 토글 상태는 화면을 떠날 때 초기화된다.
  마스킹은 실제 길이와 무관한 고정 길이(`••••••••`)로 표시한다 — 길이도 정보다.
  토글 상태는 저장되지 않는 `remember` 에 둔다 (UX-00b).
- 각 필드에 복사 버튼. 복사 시 민감 플래그 + 자동 삭제 ([LOCK-07](06-lock-policy.md)).
  비밀이 아닌 필드(사용자명 등)를 복사할 때도 민감 플래그를 단다 — 금고에서 나가는 모든 값에 같은 규칙.
  자동 삭제는 M7 에서 붙는다.
- 로그인 항목: 정책 요약과 위반 목록을 보여준다.
  - 위반이 없고 정책이 입력돼 있으면 "정책 충족" 표시. 단, **검사할 수 있는 규칙**(필수·금지 문자 종류,
    길이, 특수문자 집합, 연속 문자, 공백, 변경 주기 중 하나)이 하나도 없으면(원문 메모만 있는 경우 등)
    충족·위반 판정을 표시하지 않는다. 검사하지 않은 것을 충족했다고 말하지 않는다.
  - 기록된 규칙을 요약해 보여준다 (예: "8~20자", "대문자 필수", "허용 특수문자: !@#").
  - 정책 미입력이면 "비밀번호 규칙 기록하기" 유도 (DM-10 `NotConfigured`).
  - `rawNote` 는 그대로 전문 표시.
  - `passwordUpdatedAt` 기준 경과일 표시.
- URL은 텍스트로만 보여준다. **외부 브라우저로 열지 않는다** (1차 범위 밖, 공격면 증가).
- 수정 / 삭제. 삭제는 확인 다이얼로그 + 즉시 영구 삭제 (휴지통 없음).

## UX-06 항목 편집 (공통)

- 타입은 생성 시 결정되고 이후 변경 불가.
- `title` 필수. 나머지는 선택.
- 뒤로 가기 시 변경사항이 있으면 "저장하지 않고 나가기" 확인.
- 저장은 트랜잭션 하나 (DM-11).
- 입력 필드에 자동완성·학습이 걸리지 않게 한다 (`KeyboardType.Password`,
  `autoCorrect = false`, IME 개인화 비활성).

  **구현 (Compose 1.10 소스로 확인)**: `KeyboardOptions` 로는 `IME_FLAG_NO_PERSONALIZED_LEARNING` 을
  설정할 수 없고, `autoCorrect = false` 는 자동수정 플래그를 뺄 뿐 학습을 막지 않는다.
  `KeyboardType.Password` 는 학습을 막지만 많은 키보드가 영문 자판으로 강제 전환해 한글 메모를 쓸 수 없다.
  그래서 **앱 루트에 `InterceptPlatformTextInput` 을 씌워** 모든 입력 세션의 `EditorInfo` 에 이 플래그를
  더한다. 제목·사용자명처럼 비밀이 아닌 필드도 포함한다 — 어떤 계정이 있는지 자체가 메타데이터다
  ([01](01-threat-model.md) 보호 대상 '높음').
  - 한 줄 비밀 필드(비밀번호, 카드번호, CVC, PIN, 신분증 번호)는 `SecureTextField` + 표시 토글.
    숫자만인 필드는 `KeyboardType.NumberPassword`.
  - 여러 줄 비밀 필드(메모, 메모 본문)는 일반 입력란. 학습 차단은 루트 인터셉터가 맡는다.

## UX-07 비밀번호 정책 편집

로그인 항목 편집 화면 안의 **접을 수 있는 섹션**. 기본 접힘.
정책 입력은 부가 기능이므로 기본 입력 흐름을 방해하지 않아야 한다.

- 길이: 최소 / 최대 숫자 입력.
- 문자 종류 4개(대문자/소문자/숫자/특수문자): 각각 `모름 / 필수 / 허용 / 금지` 선택 (DM-09).
  **기본값은 `모름`.**
- 허용 특수문자 / 금지 특수문자: 텍스트 입력. 서비스 안내문에서 복사해 붙이는 사용을 가정한다.
- 연속 문자 제한, 공백 금지, 변경 주기(일).
- **규칙 원문 메모** (`rawNote`): 여러 줄 입력. 구조화 필드로 표현 못 하는 규칙을 적는 곳.
- 섹션 하단에 현재 입력된 비밀번호의 실시간 검사 결과를 보여준다 — 정책을 적는 즉시 피드백을 준다.
- **아무 규칙도 입력하지 않으면 정책 행을 만들지 않는다** (모든 칸이 비었고, 문자 종류가 전부 `모름`,
  공백 금지 꺼짐, 원문 메모 비어 있음). 그래야 상세 화면이 "충족"이 아니라 "규칙 기록하기"를 보여준다.
- 숫자 칸(최소·최대 길이, 연속 문자, 변경 주기)은 비어 있거나 1 이상의 정수여야 한다. 최소 ≤ 최대.
  어기면 저장 버튼이 비활성화된다.
- 변경 주기 재계산(DM-03)은 **목록 화면이 시작될 때마다** 한다 — 해제 직후, 상세에서 돌아올 때,
  잠금 없이 포그라운드로 돌아올 때 모두 해당한다. 판정 함수는 DM-10 평가기와 같은 것을 쓴다.

## UX-13 접근성·입력

- 모든 아이콘 버튼에 `contentDescription`.
- 비밀 필드의 마스킹 상태를 스크린리더에 알린다 ("숨겨짐" / "표시됨").
- 최소 터치 타깃 48dp.
- 글꼴 크기 200%에서 레이아웃이 깨지지 않는다.
