# 08. 테스트 전략과 검증 기준

[09](09-roadmap.md)의 각 마일스톤은 여기 정의된 테스트가 통과할 때 "완료"다.
"동작하는 것 같다"는 완료가 아니다.

## 테스트 레이어

| 레이어 | 대상 | 위치 |
|--------|------|------|
| JVM 단위 | `data/policy`, 백업 포맷 직렬화, 상태머신 로직, 백오프 계산, `vault_meta` 레이아웃·원자적 교체 | `test/` |
| 계측 (Android) | Argon2 성능, Keystore·생체, Room+SQLCipher, 마이그레이션, 세션(실제 Argon2id 위에서) | `androidTest/` |
| Compose UI | 핵심 플로우 (해제 → 목록 → 상세 → 편집) | `androidTest/` |
| 수기 | 생체 재등록, 기기 간 백업 복구, FLAG_SECURE 실제 확인 | 체크리스트 |

Keystore·생체·SQLCipher는 실제 구현을 쓴다 — **모킹하면 검증 의미가 사라지는 영역**이다.
계측 테스트가 필수인 이유다.

### 잠금 ([06](06-lock-policy.md))

| ID | 케이스 | 통과 기준 |
|----|--------|-----------|
| TST-08 | 잠금 트리거 | 타임아웃·백그라운드·수동·화면꺼짐 각각에서 상태가 `LOCKED` 로, DB 핸들이 닫히고, VK가 0으로 |
| TST-08 | 시스템 시간 조작 | 시간을 과거로 되돌려도 유휴 타임아웃과 백오프를 우회할 수 없다 (단조 시계 사용 확인) |
| TST-08 | 백오프 | 5/6/7/8회 실패 시 대기 시간이 LOCK-05 표와 일치. 앱 재시작 후에도 유지 |
| TST-08 | 전환 중 잠금 | 해제·생성·복구 도중에 온 백그라운드 전환·화면 꺼짐이 끝난 뒤 적용된다 — 상태가 `LOCKED`, DB 핸들이 닫히고, 복구한 항목은 남는다. 유휴 판정은 미뤄지지 않는다 (LOCK-03) |
| TST-08 | 파일 선택기 | 선택기가 떠 있는 동안 백그라운드 즉시 잠금만 보류된다. 오래 머물면 돌아오는 순간 유휴 판정으로 잠긴다. 판정을 통과하면 선택기의 결과가 상호작용으로 세어진다 (LOCK-03) |
| TST-08 | 잠금 중 `withVaultKey` | 실패 결과 반환. 크래시하지 않는다 |
| TST-08 | 잠금 시 ViewModel 폐기 | 잠기는 즉시, 컴포지션 없이 금고 분기의 ViewModel 이 비워진다 (LOCK-04 4 단계) |
| TST-08 | 키보드 입력 | `InputConnection` 편집 호출이 상호작용으로 세어진다. 읽기 호출은 세지 않는다 (LOCK-03) |

## 정적·구성 검증

| ID | 항목 | 확인 방법 |
|----|------|-----------|
| TST-12 | 릴리스 빌드에 로그 없음 | R8 매핑·bytecode 확인 또는 `Log` 호출 제거 규칙 검증. 비밀 보유 타입의 `toString()` 마스킹 단위 테스트 |
| TST-13 | 매니페스트 | **릴리스의 머지된** 매니페스트에서 확인한다 (소스 매니페스트로는 부족하다 — 추이 의존성이 컴포넌트를 주입한다. 디버그는 `ui-tooling`·`ui-test-manifest` 가 exported 액티비티를 넣으므로 기준이 아니다). 아래 예외 외 권한 0개(`INTERNET` 포함), `allowBackup=false`, `MainActivity` 외 `exported=false`, `dataExtractionRules` 적용 |
| TST-13 | 허용된 예외 4건 | ① `<자기 패키지>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` — `androidx.core` 가 자동 선언하는 `signature` 보호 수준 권한이며 런타임 권한이 아니다. ② `USE_BIOMETRIC`, `USE_FINGERPRINT` — `androidx.biometric` 이 선언하는 `normal` 보호 수준 권한. 설치 시 자동 부여되며 사용자에게 묻지 않는다. CRY-07 생체 해제에 필요하다. ①②는 NFR-03(런타임 권한 0개) 위반이 아니다. ③ `androidx.startup.InitializationProvider`, ④ `androidx.room.MultiInstanceInvalidationService` — 둘 다 `exported=false` 이므로 SEC-08 위반이 아니다. ④는 Room 이 선언하며, 이 앱은 다중 인스턴스 무효화를 켜지 않으므로 실행되지 않는다. **이 외의 항목이 보이면 회귀다** |
| TST-13 | 의존성 | 네트워크 라이브러리가 추이적으로 들어오지 않았는지 의존성 트리 확인 |

## 수기 체크리스트 (릴리스 전)

- [ ] 최근 앱 화면에서 금고 내용이 보이지 않는다 (LOCK-06)
- [ ] 스크린샷이 차단된다 (실기기. 에뮬레이터는 동작이 다를 수 있다)
- [ ] 비밀번호 복사 후 지정 시간에 클립보드가 비워진다 (LOCK-07)
- [ ] 지문을 추가 등록한 뒤 생체 해제가 거부되고 안내가 뜬다 (SEC-11)
- [ ] 기기 A에서 내보낸 백업을 기기 B에서 복구할 수 있다 (SEC-04)
- [ ] 비행기 모드에서 모든 기능이 동작한다 (NFR-04)
- [ ] 저사양 실기기에서 해제가 1.5초 안에 끝난다 (NFR-01)
- [ ] 글꼴 200% / 다크 모드에서 레이아웃이 깨지지 않는다 (UX-13)
- [ ] 마스터 비밀번호 변경 직후 구 비밀번호로 열리지 않고, 항목이 모두 남아 있다
- [ ] 자동 잠금 15초에서 파일 선택기에 15초 넘게 머문 뒤, 잠금을 풀고 내보내기·가져오기를 끝낼 수 있다 (LOCK-03)
- [ ] 내보내기에서 위치를 고른 뒤 취소하면 빈 파일이 남지 않는다. 기존 백업 파일을 골랐다가 취소하면 그 파일은 그대로다 (BK-03).
  실제 선택기의 문서여야 확인된다 — 테스트가 만든 파일 경로로는 삭제 경로를 지나지 않는다

## 기기 테스트에서 겪은 함정

기기에서 앱을 직접 조작해 확인할 때 같은 시간을 다시 쓰지 않기 위한 기록.

| 함정 | 대처 |
|------|------|
| `FLAG_SECURE` 때문에 `adb screencap` 은 앱 영역이 검게 나온다 | 화면 모양은 Compose 테스트의 `captureToImage` 로 임시 캡처해서 본다. 실제 앱 화면은 `uiautomator dump` 의 글자로 확인한다 |
| `adb shell input text` 는 `Activity.onUserInteraction` 을 지난다. 실제 소프트 키보드는 지나지 않는다 | 유휴 잠금 같은 키보드 관련 동작은 화면의 키보드 키를 직접 눌러 확인한다 (`uiautomator dump --windows` 로 키 위치를 얻는다) |
| 에뮬레이터의 Gboard 가 주입한 키를 삼킨다. 비밀번호 입력란은 되고 일반 입력란은 안 된다. 에뮬레이터를 다시 켜도 그대로일 수 있다 | 일반 입력란의 입력은 계측 테스트나 실기기로 확인한다. 삼성 키보드에서는 주입이 된다 |
| 백그라운드에서 바로 돌아오면 목록 쿼리가 다시 시작되지 않아 복귀 결함이 드러나지 않는다 | 백그라운드 복귀는 5초 넘게 기다린 뒤 확인한다 |
| 실기기는 테스트 도중 화면이 꺼지고 잠긴다. Compose 테스트가 "No compose hierarchies found" 로 실패한다 | 테스트하는 동안 화면을 켜 둔다 (주기적으로 `input keyevent KEYCODE_WAKEUP`) |
| 기기가 둘 이상 연결돼 있으면 계측 테스트가 전부에서 돈다 | `ANDROID_SERIAL` 로 대상을 정한다 |
| 에뮬레이터를 오래 켜 두면 느려져 Compose 테스트가 유휴 대기 시간 초과로 실패한다 | 단독으로 다시 돌려 구분한다. 계속되면 에뮬레이터를 다시 켠다 |
| RAM 2GB 에뮬레이터는 파일 선택기가 뜨는 동안 앱 프로세스를 죽인다 (lowmemorykiller). 스왑이 차면 포그라운드 앱도 죽인다. 유휴 잠금으로 잠긴 것처럼 보인다 | `emulator -memory 4096` 으로 켠다. 프로세스가 죽었는지는 `pidof` 와 logcat 의 `lowmemorykiller: Kill` 로 구분한다 |
| `adb shell input` 의 글자와 터치는 대화상자(별도 창)에서는 `Activity.onUserInteraction` 을 지나지 않는다. 재인증 대화상자에 글자를 넣는 동안 유휴 잠금이 걸린다 | 대화상자를 지나는 흐름은 자동 잠금을 30초 이상으로 두고 몬다 |
| 파일 선택기의 격자 보기에서 파일 이름으로 찾은 첫 노드는 미리보기 영역이다. 누르면 고르지 않고 "Open with" 가 뜬다 | 이름이 정확히 일치하는 `TextView` 를 누른다 |

## 하지 않는 테스트

| 항목 | 이유 |
|------|------|
| 루팅 기기에서의 방어 | [01](01-threat-model.md) Out of scope |
| 메모리 덤프에서 키 부재 확인 | JVM에서 보장 불가. SEC-12는 완화 조치 |
| 암호 알고리즘 자체의 정확성 | 플랫폼·라이브러리 신뢰. 우리는 **사용 방식**만 테스트한다 |
